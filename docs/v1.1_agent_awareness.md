# Judgment Layer: v1.1 Addendum, Agent Awareness

**Status:** Direction agreed. Step 1 is built. Items marked *open* are undecided.
**Builds on:** `prototype_plan.md` (v1). Nothing in v1 changes. This adds a sensor class and a
second source of assumptions.

---

## 1. Why

Most code is now written by coding agents, not typed by hand. v1 sees an agent session only
through its side effects, such as file edits and commits. Worse, agent shell commands are
invisible, because the terminal hooks fire on an interactive prompt and agents don't use one.

Agents also make available something a human never does: **stated intent and stated
reasoning.** The prompt says why the work is happening, and the agent's own messages say what
it assumed. v1 had to answer "insufficient evidence" for exactly that gap.

> A human's reasoning is invisible. An agent's reasoning can be asked for.

---

## 2. Two layers of capture

| Layer | What | Needs agent cooperation? | Role |
|---|---|---|---|
| **Passive** | Prompts, tool calls, shell commands and output, the agent's visible narrative | No | Ground truth for what the agent actually *did* |
| **Active** | The agent records assumptions and decisions through a Grymbl tool | Yes | What the agent *believes* |

The passive layer is the foundation. The active layer is valuable, but agents follow
instructions inconsistently, so nothing should depend on it.

**Limit:** current Claude models don't expose their raw internal reasoning, only a summary at
most. We capture what the agent *writes*: its explanations, plans, to-do lists and claims.

---

## 3. Epistemic rule (locked)

**What an agent says about its own work is a claim, not evidence.**

- Assumptions an agent records, or that are pulled from its narrative, are stored as
  `unverified`. They are never `valid` just because the agent said so.
- The strongest signal is the **gap between what the agent said and what it did**: "tests
  pass" with no passing test run, or "only touched the parser" with a diff in `auth/`.
- The v1 evidence rule (§11) still applies. The agent's narrative is context for Sonnet, not
  support for a conclusion.

---

## 4. Build sequence

### Step 1: Passive capture for Claude Code *(built)*

- `grymbl init` installs Claude Code hooks for the watched repo.
- New entry point `grymbl capture-agent` reads the hook's JSON from stdin. Like every capture
  command, it exits 0 silently and logs failures.
- Events:
  - `agent_prompt`: the user's prompt (redacted) and the session id.
  - `agent_tool`: tool name plus a compact, redacted summary. Shell commands and their exit
    status are recorded, which closes v1's blind spot. File edits record only the path,
    because the file sensor already captures the content.
  - `agent_turn_end`: the agent's visible narrative for the turn (redacted), read from the
    session transcript.
- Correlation: one prompt and the work that follows it make a natural episode, so no
  time-window guessing is needed for agent work.
- Sonnet sees the prompt and narrative, clearly labelled as the agent's claims.

**Verified against a live Claude Code 2.1 session:**
- The hooks used are `UserPromptSubmit` (field `prompt`), `PostToolUse` (Bash `tool_response`
  has `stdout` and `stderr`), `PostToolUseFailure` (non-zero Bash exits arrive here, with
  `error: "Exit code N
…"`), and `Stop` (`last_assistant_message` plus a transcript path).
- Thinking blocks in the transcript are empty, so the narrative is the agent's written text.
- `Stop` must run synchronously, because a headless session drops async hooks when it exits.
  The other hooks run async so they never slow the agent down.
- Agent edits are atomic saves: the agent writes a temp file, deletes the original, and renames
  the temp file into place. The watcher ignores `*.tmp.*` files and waits 2 seconds before
  trusting a deletion. This also fixed false "deleted logic" escalations for human editors
  that save the same way.
- Only one watcher may run per repo (OS-level lock). Two watchers duplicate every event.
- Each turn's narrative is capped at 20k characters, keeping the start and marking the cut.

### Step 2: Active declaration (MCP + fallback)

- `grymbl mcp` runs an MCP server with `record_assumption` and `record_decision`. One server
  covers Claude Code, Cursor, Codex and other agents that support MCP.
- Fallback for any agent with a shell: `grymbl note --assumption "…"`.
- A short instruction block tells the agent to record only *non-obvious* assumptions and
  decisions, not to narrate everything, which would cost tokens and hurt its task
  performance.
- Records go straight to `ASSUMPTION` nodes as `unverified`, linked to the episode.

### Step 3: Interventions to the agent

- Before the agent edits a file with escalated history, Grymbl injects the relevant history
  into the agent's context, e.g. "last change here broke token expiry; evidence: …".
- This answers the delivery-channel question left open in v1 §10: the best recipient of a
  warning is often the agent about to repeat the mistake.
- Silence stays the default. The same bar as v1 applies: only history that supports the
  warning, and nothing on routine work.

## 5. Configuration principles (locked)

- **Local over shared.** Prefer gitignored, per-machine config (`.claude/settings.local.json`,
  `CLAUDE.local.md`). Grymbl must not quietly rewrite a repo's committed agent setup.
- **Where a shared file has to change** (e.g. `AGENTS.md`), use one clearly marked Grymbl
  block, ask first, and make it removable with one command.
- **Redaction applies to everything:** prompts, tool inputs, command output and narrative
  pass through `redact()` before storage.
- **Adapters, not magic.** There's no universal agent standard. The order is Claude Code hooks
  (deepest), then MCP and `AGENTS.md` (widest), then per-tool adapters as needed.

---

## 6. Schema impact

- **New event kinds:** `agent_prompt`, `agent_tool`, `agent_turn_end` (Step 1), `agent_note`
  (Step 2).
- **`EPISODE`** gains `agent` (e.g. `claude-code`, or null for human work) and `intent` (the
  redacted prompt, if any).
- **`ASSUMPTION`** gains `origin`: `inferred` (Sonnet, v1) or `declared` (the agent, Step 2).
- There are no new relationship types, so this stays within the v1 schema's intent.
